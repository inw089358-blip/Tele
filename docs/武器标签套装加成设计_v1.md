## 1. 机制定义

- 每把武器固定 `2` 个 `build_tags`。
- 标签计数只统计 `equipped_weapons`（装备槽），不统计背包/溢出。
- 单标签计数上限为 `6`。
- 阈值档位固定为：`2 / 3 / 4 / 5 / 6`。
- 当前生效档位取“已达成最高档”，不是累计叠层。
- `1` 层不触发加成。

## 2. 结算顺序

1. 读取当前 6 槽已装备武器。  
2. 汇总每件武器的 `build_tags`，按标签计数并封顶 `6`。  
3. 逐标签求最高激活档位（2~6）。  
4. 读取对应 `tag_defs.<tag>.tiers.<tier>.effects`。  
5. 若 `weapon_tag_bonus_rules.enabled = true`，将效果映射到现有属性系统。  
6. 若 `enabled = false`，仅展示层级预览，不改动战斗属性。

## 6. UI展示规范（Shop属性面板）

- 区块标题：`武器标签加成`。
- 每条显示格式：`标签名 当前层数/6 激活档位 下一档位`。
- 示例：`鹰眼 3/6  激活T3  下档T4`。
- 若已封顶：显示 `已封顶`。
- 若系统未启用：在区块底部显示 `（规则未启用，当前仅预览层级）`。
