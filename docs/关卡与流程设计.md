## 2. 战斗关卡详细设计

### 2.1 单局战斗结构

每局战斗由**多个波次(Wave)**组成，每个波次包含：

```
波次流程:
┌─────────────────────────────────────────────┐
│ Wave N 开始                                  │
│  ├── 显示波次提示文字 ("WAVE 3")             │
│  ├── 倒计时 3秒准备时间                      │
│  ├── [生成阶段]                              │
│  │   ├── 按配置表生成敌人                     │
│  │   └── 间隔: 每0.5-2秒生成一批              │
│  ├── [战斗阶段]                              │
│  │   ├── 玩家自动攻击 + 移动                  │
│  │   ├── 敌人AI行为                          │
│  │   └── 掉落物管理                          │
│  └── [判定阶段]                              │
│      ├── 存活敌人 > 0? → 继续战斗             │
│      ├── 存活敌人 = 0? → 波次结束             │
│      └── 超时(可选)? → 失败惩罚                │
└─────────────────────────────────────────────┘
         │
         ▼ 所有波次完成?
    ┌────┴────┐
    │是       │否
    ▼         ▼
[进入奖励]  [下一波次]
```

### 2.3 关卡进度树

采用线性章节推进，教学关不计入 15 关主线。主线完成后进入真最终Boss战。

```
教程关(不计入总关数)
  ↓
第1-4关  -> 第5关 Boss-1 -> 补给站A
  ↓
第6-9关  -> 第10关 Boss-2 -> 补给站B
  ↓
第11-14关 -> 第15关 Boss-3 -> 终幕准备
  ↓
真最终Boss（第16战，主线通关战）
```

#### 2.3.1 主线章节结构（暂定）

| 章节 | 关卡范围 | 章节定位 | 章节终点 |
|------|----------|----------|----------|
| Chapter I | 第1-5关 | 入门 + 构筑启蒙 | 第5关 Boss-1 |
| Chapter II | 第6-10关 | 中压节奏 + 机制叠加 | 第10关 Boss-2 |
| Chapter III | 第11-15关 | 高压考核 + 构筑验证 | 第15关 Boss-3 |
| Final | 真最终Boss | 终局机制整合 | 主线结局 |

#### 2.3.2 解锁规则（暂定）

- 通过教学关后解锁第1关。  
- 主线按顺序推进，通关当前关卡解锁下一关。  
- 第5/10/15关固定为章节Boss关。  
- 第15关通过后，解锁真最终Boss战入口。  
- 真最终Boss战前允许进入“终幕准备”界面（可视为最后一次补给流程）。

#### 2.3.3 章节Boss后补给站（Hub）需求

每次击败章节Boss后进入补给站，作为战斗间的策略与资源调整节点。

**补给站核心功能**

1. **状态回复（消耗货币）**  
- 回复生命值：按比例收费（如 25% / 50% / 100% 三档）。  
- 异常清除：可单独付费移除负面状态（若系统启用异常状态）。  

2. **道具购买（消耗货币）**  
- 常驻增益道具：本局持续生效（如攻击/攻速/移速小幅强化）。  
- 消耗型道具：下一关生效一次（如开局护盾、紧急治疗包）。  
- 稀有槽位：低概率刷新高价值道具，价格显著更高。  

3. **属性强化（消耗货币）**  
- 提供 3-5 个可升级节点（攻击、生存、功能向）。  
- 单节点可重复购买但存在递增价格与等级上限。  
- 强化效果需与战斗内升级区分，避免完全重叠。

**经济与平衡约束**

- 玩家击败Boss后至少可承担 1 次中等回复或 1 件基础道具。  
- 同一补给站中，回复和强化不能同时“全买满”，必须有取舍。  
- 章节越后期，物价与收益同步抬升，保持决策压力。

**验收标准（DoD）**

- 击败第5/10/15关Boss后，100% 进入对应补给站流程。  
- 玩家在补给站至少有 2 类可执行消费选择（回复/道具/强化）。  
- 货币不足时有明确反馈，不出现无法返回主流程的卡死状态。  
- 离开补给站后，购买与回复结果在下一关正确生效。

### 2.4 事件化节奏节点设计（30s / 60s / 90s）

为避免关卡仅体现为“数值递增”，每个战斗单元采用固定的 90 秒节奏骨架，并在固定时间点触发具有辨识度的事件。  
单局 5-8 分钟由 3-4 个节奏单元组成，形成可预期但不重复的战斗叙事。

#### 2.4.1 节奏节点总原则

1. **单节点单主变化**：每个节点只引入一种主压力来源，保证可读性。  
2. **先预警后生效**：事件必须提供 0.8-1.2 秒的视觉或音频预警。  
3. **90 秒必有焦点战**：90 秒节点固定为精英或迷你Boss高潮。  
4. **节点后呼吸窗口**：每次 90 秒节点结算后，提供 5-8 秒低压整理期。  
5. **强度互斥降级**：环境压力与精英重叠时，环境效果强度下调 20%-30%。

#### 2.4.2 节奏节点类型定义

| 时间点 | 事件类型 | 设计目的 | 可用手段 |
|--------|----------|----------|----------|
| **30s** | 刷怪模式变化 | 打破站桩节奏，强制换位 | 扇区刷怪、环形包夹、追踪单位引入 |
| **60s** | 环境压力介入 | 改变场地规则，制造决策负担 | 危险地带、视野干扰、移速扰动、周期脉冲 |
| **90s** | 精英/小高潮触发 | 形成记忆点并验证构筑 | 1-2精英、护盾机制、阶段化技能、击杀奖励 |

#### 2.4.3 节奏节点卡模板（Rhythm Card）

```yaml
rhythm_card:
  stage_id: stage_xxx
  timeline_unit: 90s
  node:
    - time: 30s
      type: spawn_pattern_shift
      event_name: ""
      telegraph: ""         # 预警方式（文字/音效/地面标记）
      main_effect: ""       # 主效果（只写一项）
      duration: ""          # 生效时长
      fail_penalty: ""      # 未处理代价
      clear_reward: ""      # 通过收益
      fallback_event: ""    # 事件失败时替代方案（降压）
    - time: 60s
      type: environment_pressure
      ...
    - time: 90s
      type: elite_climax
      ...
```

#### 2.4.5 事件池与复用规则

1. 30 秒节点从 `SpawnPatternPool` 抽取，不与上一单元重复。  
2. 60 秒节点从 `EnvironmentPool` 抽取，连续两单元不得使用同类干扰。  
3. 90 秒节点从 `ElitePool` 抽取，若玩家 DPS 低于阈值则优先单精英方案。  
4. 同一关内相同事件最多出现 2 次，第 3 次必须替换为变体版本。  
5. 后续关卡沿用同一骨架，但必须更换主题表达和应对方式。

#### 2.4.6 风险控制与降级策略

| 风险场景 | 触发条件 | 自动降级 |
|----------|----------|----------|
| 压力叠加过高 | 环境事件与精英事件重叠超过 5s | 环境伤害系数降至 70% |
| 玩家濒死连锁 | 玩家 HP < 30% 且 15s 内再次受击 | 暂停新增刷怪 3s 并提高回复掉落权重 |
| 场面拥挤 | 同屏敌人超过性能阈值 | 优先移除低威胁杂兵，保留事件核心单位 |

#### 2.4.7 验收标准（DoD）

- 玩家首次进入该关时，能够在无教程情况下识别至少 2 种节点预警。  
- 30s/60s/90s 节点触发误差不超过 ±1 秒。  
- 每个 90 秒节点后都出现 5-8 秒的明显低压窗口。  
- 三个时间点事件均能改变玩家行为，而非仅提升敌人数值。  
- 在标准构筑下，90 秒节点精英战平均耗时控制在 20-40 秒。

## 3. 奖励系统设计

### 3.1 奖励触发时机

| 触发事件 | 奖励类型 | 选择数量 | 时间限制 |
|----------|----------|----------|----------|
| **升级** | 属性提升/新技能 | 3选1 | 无限（暂停游戏） |
| **关卡完成** | 稀有道具/特殊能力 | 3选1 | 无限 |
| **宝箱开启** | 随机物品 | 1个 | 即时获得 |
| **成就达成** | 固定奖励 | 直接获得 | - |
| **隐藏要素** | 特殊内容 | 直接获得 | - |

### 3.4 奖励选择算法

```python
def generate_reward_choices(player_data, context):
    """
    生成3个奖励选项的算法逻辑
    """
    available_pool = get_available_rewards(player_data.unlocked_rewards)
    
    # 过滤掉已达上限的奖励
    filtered = filter_by_stack_limit(available_pool, player_data.current_build)
    
    # 根据权重随机抽取3个（保证不重复）
    choices = weighted_random_sample(filtered, k=3)
    
    # 智能调整：如果玩家缺少某类属性，略微提高相关奖励权重
    if player_data.damage < threshold:
        boost_weight(choices, category="attack")
    
    return choices
```

### 4.2 敌人生成机制

```godot
# EnemySpawner.gd
class_name EnemySpawner

@export var spawn_margin: float = 50.0  # 屏幕外生成距离
@export var min_distance_from_player: float = 200.0

func spawn_enemy(enemy_type: String, count: int):
    for i in range(count):
        var pos = get_valid_spawn_position()
        var enemy = create_instance(enemy_type, pos)
        add_child(enemy)
        # 生成特效：像素凝聚动画
        play_spawn_effect(pos)

func get_valid_spawn_position() -> Vector2:
    var viewport = get_viewport_rect()
    var attempts = 0
    while attempts < 10:
        # 在屏幕边缘外随机选择位置
        var edge = randi() % 4  # 上右下左
        match edge:
            0: pos = Vector2(randf_range(0, viewport.size.x), -spawn_margin)
            1: pos = Vector2(viewport.size.x + spawn_margin, randf_range(0, viewport.size.y))
            # ... 其他边
            
        # 确保离玩家足够远
        if pos.distance_to(player.global_position) > min_distance_from_player:
            return pos
        attempts += 1
    return fallback_position()
```


### 6.2 肉鸽随机性控制

为了保证每次游玩体验的质量，采用**引导式随机**:

1. **保底机制**: 每5次未获得攻击类奖励，下一次必定出现攻击选项
2. **防绝望机制**: HP低于30%时，下次奖励池中恢复类物品权重×3
3. **多样性保证**: 同一类别奖励不会连续出现超过2次
4. **成长平滑**: 后期关卡的基础掉落经验值提高，避免后期升级停滞
